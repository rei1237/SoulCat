## 같은 장의 상담 깊이

- 고등어: 핵심 결론 → 계산 근거와 이유 → 생활 사례 → 첫 행동.
- 연어: 핵심 결론 → 반복 원인 → 상황별 차이 → 생활 사례 → 실행.
- 광어: 근거 연결 → 강점과 부담 → 대안 비교 → 상황별 사례 → 선택 기준.
- 참치: 전문 근거 → 상충과 예외 → 조건별 해석 → 생활 사례 → 행동 계획 → 점검 기준.
- 조합: 체계별 근거, 일치와 상충, 조건별 해석, 사례, 선택 기준, 점검 계획.
- 종합: 분야별 근거, 연결과 한계, 다른 가능성, 조건별 사례, 우선순위, 실행과 점검.

각 장에 고유 key, 질문, 제외 논점, 사용할 계산 근거, 필수 소제목을 저장한다. 같은 제목을 단순히 길게 늘리라는 지시 대신 해당 등급의 설명 단계를 요구한다. 지정된 소제목이 빠지면 분량을 채웠더라도 실패한다.

- SWISS와 기존 SoulCat 시간 보정은 덮어쓰지 않았다. 출생시간 미상, 계산 실패, 달력의 한계는 기존 계산 결과의 제한 사항을 전달한다.

원본 서비스 파일 수정 및 배포는 수행하지 않았다. 계산 정확성을 등급에 따라 낮추지 않고, 결과 설명에 전달하는 전문 근거 범위를 분리했다.

## 프롬프트·품질·예산 처리

새 버전은 `destiny-book-v4` / `chapter-v4`다. 새 본문은 소제목과 짧은 문단을 가진 blocks로 저장하며 기존 v3 analysis 형식과 구매 당시 목차 계약은 유지한다.

장별 및 전체 최소 분량, 필수 설명 단계, 근거 ID, 동일·유사 문단, 일부 반복 문장, 하위 등급 전문 해석, 확률·확정적 주장 패턴을 검사한다. 프롬프트는 없는 트랜짓·시기·상대 정보, 체계 혼용, 일반론으로 분량 채우기를 금지한다. 문자열·구조 검사는 의미 수준의 모든 중복이나 근거 없는 해석을 검출하는 장치가 아니므로 실제 모델의 별도 평가가 필요하다.

분량 부족은 해당 장만 한 번 보완한다. 보완 시도를 먼저 저장하므로 재진입해도 추가 호출하지 않는다. 보완 후에도 부족하면 실패 처리하고 완료로 표시하지 않는다. 결과를 알 수 없는 타임아웃은 UNCERTAIN으로 남기며 자동 재호출하지 않는다. 기존 권한을 삭제하거나 새 결제를 요구하지 않는다.

출력 상한은 전체 책이 아닌 **장별 호출 기준**으로 고등어·연어 4,096토큰, 광어 이상 8,192토큰이다. 실제 상한을 입력 토큰 계산 및 비용 예약에 반영한다. 모델·장 수·manifest 버전·출력 상한이 맞는 새 상품 비용 검증값이 필요하며 기존 검증값은 거부한다. 새 실제 비용 검증값을 만들어 넣거나 실 호출을 수행하지 않았다.

## 영냥이의 방과 읽기 화면

본인이 소유한 결제 완료·권한 유효·생성 완료 결과를 선택해 Mock 상담한다. 서버에서 소유권과 선택 결과를 확인하고, 관련 장의 근거·등급 범위·설명 깊이를 사용한다. 대화는 최근 4개만 문맥으로 제한하며 결과 변경 시 대화를 초기화한다. 하위 결과로 용신·대운 등 전문 해석을 우회 요청하면 범위 안내를 반환한다.

기존 v3 결과는 그대로 읽을 수 있지만 새 방 상담은 v4 결과를 대상으로 한다. 방 상담은 local/staging의 명시적 Mock 설정에서만 실행하며 production 및 실 LLM 연결은 차단한다. 새 상담 가격·횟수 정책·영구 대화 저장 기능은 추가하지 않았다.

읽기 화면은 소제목 본문, 기존 챕터 이동, 읽음 표시와 이어 읽기를 지원한다. 상품 화면에는 실제 목차와 등급별 설명 깊이를 표시했다. 390px와 1280px에서 고등어·참치 읽기, 저장 후 재진입, 목차, 보관함 기반 방 상담을 확인했다. 해당 검사 화면의 가로 넘침은 없고 axe 위반은 0건이다. 이는 앱 전체 접근성 인증은 아니다. [화면 검사 기록](reading-v4-ui-verification.json)

- `npm run typecheck`: 통과.

## 남은 확인 사항

실제 LLM의 문장 품질, 해석의 의미상 중복·사례의 적절성, 목표 분량 도달률, 호출 비용 및 긴 책의 체감 대기 시간은 아직 검증하지 않았다. 전문가 수준의 실제 상담 품질을 달성했다고 주장하지 않는다. 승인된 실 호출 평가 뒤 새 비용 검증값을 등록해야 한다. 실제 결제, 운영 DB 변경, 원본 서비스 수정, 배포는 이번 작업에 포함하지 않았다.
